# 第一版交付卡：从需求原文到可审查的故事草稿

日期：2026-11-14。编写：Codex。状态：**交付范围建议，待负责人确认；不是已实现说明或实施授权。**

本次已拆出 [P1-1 实施任务](steps/P1_1_TASK.md)，由负责人要求重新安排后限定启动；本卡的其余范围仍是后续建议，不是全部一次实施。

阅读入口：[文档导航](../README.md)。方向依据：[设计原则](../product/DESIGN_PRINCIPLES.md)；技术细节仍在 [B1 提案](../design/B1_PROJECT_INIT_AI_PROPOSAL.md) 与 [AI 规划](../design/AI_CORE_PLAN.md) 中评审。本卡只收敛“交付什么、如何验收”，不另起一套技术设计。

## 1. 为谁解决什么问题

给已有代码项目、希望补齐验收依据的开发者使用。用户提供需求文档，选择模型连接；FlowTree 产出可追溯、可校验、明确待确认的故事草稿，供用户审阅修改。第一版不要求开发者手工拼接 FlowTree 主机工作区配置才能完成这条链路。

**价值：减少整理需求的操作，不把 AI 起草或格式正确包装成需求正确。** 这是完整产品的第一个小闭环，不等于测试生成、逻辑验收和人工反馈都已自动完成。

## 2. 用户走通的一条路径

以下是行为要求，具体命令和文件名待技术提案定案，不是当前可运行教程。

| 步骤 | 用户操作 | 工具应交付 | 能否继续的依据 |
|---|---|---|---|
| 1 接入 | 指定项目目录；首次设置用户级模型连接 | 最小项目入口；明确哪些文件归项目、哪些只在本机 | 不联网、不调用模型、不覆盖已有文件；后续命令能定位本项目 |
| 2 预览 | 指定一份需求文档，查看发送预览 | 最终目标地址、配置来源、输入范围与调用限制 | 没有隐含上传其他文件；预览不发请求、不算授权 |
| 3 起草 | 明确授权本次发送 | 故事草稿、来源与摘要、生成信息、假设/待确认项 | 至多一次模型请求；产出保持草稿，不覆盖正式故事 |
| 4 检查 | 查看草稿和检查结果 | 格式/引用问题；有来源的候选规则与待确认项可阅读 | 格式通过与规则未确认分开展示；无效输出不伪装成功 |
| 5 修改重检 | 手改草稿后重新校验 | 针对新内容的校验结果，旧结果标明不再适用 | 本步骤不需要重新调用模型或额外付费 |
| 6 审阅交接 | 对照原文检查规则和假设 | 明确下一步是负责人确认与后续映射/测试工作 | 不能自动转正或宣称逻辑/人工验收通过；具体确认交互由小批次提案明确 |

已有验证引擎继续独立运行；本卡不要求在这次交付里把新草稿直接送进真实业务测试。

## 3. 范围边界

**本次包括：** 最小项目入口、DeepSeek 首个使用配置、通用聊天协议调用边界、发送授权、单文档起草、离线校验、草稿溯源和状态，以及少量人工标注案例的评测报告。

**本次不包括：** 自动生成测试或映射、修复业务源码、agent 循环、反馈页面、验收轮次系统、多人权限、真实项目材料迁移、模型排行榜、全部历史文档整理。既有验证/页面仅允许本闭环必需的最小接入或缺陷修复。

## 4. 必须验收的结果

| 编号 | 场景与预期 | 最少证据 |
|---|---|---|
| A1 | 在新的临时 Git 项目完成整条路径，无需手工编辑 FlowTree 主机工作区 | 从项目入口开始的命令记录、生成文件清单；明确任何仍需手工操作的步骤 |
| A2 | 初始化可重复、不覆盖已有文件；项目材料与本机敏感配置分开 | 文件前后对比、Git 忽略检查；路径冲突/符号链接反例 |
| A3 | 未授权、密钥缺失、预览或离线检查时，模型请求数为零 | 本机假服务请求计数；不依赖真实密钥 |
| A4 | 授权后假服务返回合法结果，产生草稿和匹配的元数据；同名输出不覆盖 | 实际 HTTP 测试、草稿加载校验、来源与内容摘要对照 |
| A5 | 超时、鉴权/限额失败、缺文本、截断、非法 YAML、语义错误有明确失败结果 | 每类至少一条可解释的反例；不自动重试、不写正式故事、不留被当作完整输出的半组文件 |
| A6 | 文档中的指令不能改变端点、执行命令或自行确认；输入过长不静默截断 | 有恶意指令/超长输入的固定案例及输出范围检查 |
| A7 | 草稿手改后，旧校验不冒充当前结果；重新检查不调用模型 | 摘要变化与重检记录；各项状态分开展示 |
| A8 | 未配置 AI 时，现有校验/验证/证据功能继续工作 | 与改动相关的既有回归，运行于临时项目；不无故重跑 LPB |
| A9 | 用固定小样本检验规则遗漏、矛盾及无依据断言 | 冻结的输入、逐条来源与确认状态、输出、人工标签、分子分母；不能只给质量总分 |
| A10 | 负责人在自己的 DeepSeek 配置下试用一次，能理解草稿与下一步 | 单独的真实试用记录、实际请求数与用量（未知如实记录）；费用和发送须事先获授权，不算离线测试通过 |

离线完成 A1～A9 后，可以报告“离线链路通过”；A10 未做则保留“真实模型试用未核对”。不能把某个阶段完成说成整张卡已交付。

## 5. 做得好还要看什么

- 记录首次使用所需的命令数、手工配置处数、耗时；先测实际值，不承诺“只需点一次”。
- 用户是否能分清“格式有问题”“规则待确认”“服务调用失败”，失败后是否知道下一步。
- 用户能否追溯候选规则到原文；确认页面或记录的设计不能替代这项实际阅读检查。
- 评测只说明固定案例上的表现。US-23/US-24 的未确认附加规则不作标准答案，也不冒充独立留出集。

## 6. 实施分成三次可复验交付（建议）

1. **最小接入与调用：** 项目入口与用户级连接、预览/授权、假服务 HTTP、错误和调用限制。暂不生成故事。
2. **草稿与重检：** 单文档到草稿/元数据、现有严格校验器、内容变化失效、不调用模型的重检。
3. **审阅与评测：** 最小确认边界、来源逐条核对、小样本标注报告、经授权的真实试用。

每次只提交该批验证过的实现/测试/说明；不以全部总体规划完成为提交条件。具体任务由评审后的技术提案拆解，本卡不规定类名或状态机实现。

## 7. 开始实施前只需收敛的决定

- 负责人是否接受这张卡的第一版交付边界与三次拆分。
- 技术提案明确项目入口、用户级连接的读取方式及草稿重检入口，给出完整命令链。它们是实现选择，不应让用户反复选择内部字段。
- 在任何真实请求之前，负责人确认实际发送范围及调用上限；不阻塞先做离线开发。

DeepSeek 首个提供方、步骤独立、逻辑结果与人工进度分开等已确定方向，不重复征询。
