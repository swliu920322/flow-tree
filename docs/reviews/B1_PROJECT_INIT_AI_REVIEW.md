# B1 第 2 版设计复核（Codex）

日期：2026-11-14。仅设计审查，未实施、未调用模型、未修改 LPB。方向可行，但下列边界应先写清；不代替负责人确认目录和命令方案。

## 1. 本机文件位置不等于已被用户信任

恶意项目仍可附带一个未跟踪的 local.yaml，或包含指向其他文件的符号链接。只把端点移出入库配置不能保证它由用户设置。

首次确认必须同时覆盖 ai check 和 draft：前者同样会发送密钥。发请求前展示最终协议、目标地址（含路径）与配置来源；非交互环境没有明确授权就退出，不发请求。dry-run 只是预览，不能代替用户同意。可明确增加按次授权参数，不必首版实现持久信任库。

URL 要定义为 base_url 的路径前缀加相对请求路径，避免 /v1 丢失、重复拼接或 path 改变主机；拒绝嵌入凭据。首版可完全禁止重定向，避免第二次发送及密钥转发。错误与日志不要原样输出服务端响应正文，正文可能回显密钥或需求内容。接口不兼容时不得自动改协议再试。

## 2. 初始化不覆盖，也不能越出项目写文件

初始化对已存在的普通文件只报告/保留；目标 .flowtree 或待写文件若是符号链接、路径类型冲突则拒绝，不沿链接写出项目。草稿文件名不得直接采用未经约束的模型 ID，路径分隔符和越界路径应拒绝。

已有 .flowtree/.gitignore 时不能一边承诺不修改、一边声称本机配置已忽略；已有根忽略规则整体排除 .flowtree 时，子目录规则也未必能恢复跟踪。遇到这些情况明确报告需用户处理，不宣称布局已全部可入库。Git 不跟踪空目录，验收应检查文件是否被忽略，不能要求空目录出现在 git status。

## 3. 草稿和元数据的权威来源

status=draft、实际来源路径/摘要、实际模型、生成时间由工具填写，不信任模型自报。模型只给候选故事及假设/待确认项，明确一次响应如何分隔两者、如何分别校验；最终故事文件仍复用严格模型。

元数据绑定生成的故事内容摘要；故事被手改后，不继续显示旧的校验结果和待确认项为当前结果。两份文件作为一组提交输出，同名任一文件存在均不覆盖，失败不留下被计为有效草稿的半组文件。模型未列出待确认项与明确返回空列表应区别处理；空列表不等于负责人确认。

## 4. 指纹依赖的现状需修正

“故事、映射一入库就会因工作区指纹重复计入”并非当前实现的完整事实：service._spec_files 已排除本次明确读取的故事和映射文件，它们仍有独立摘要。指引、草稿、项目配置等是否排除另议；不要扩大为排除整个 .flowtree，否则会漏掉本应追踪的输入。

本批可不改指纹，但要准确列出仍未解决的材料类别，并明确验证引擎是否可直接读取新项目配置。若尚不能直接使用，应说明需显式指定路径/工作区配置，本批只是初始化与起草闭环，不宣称完整接入已完成。

## 5. 保持批次最小且可离线验证

保留 project init、ai check、draft 及 openai_chat 单协议范围；DeepSeek 只作默认配置示例，模型名实施时按官方支持值核对。连接超时与整体超时、输入/响应大小上限、输出截断/无文本等协议错误要有明确行为。超时不声称服务端未收费；不自动重试。

离线假服务需补验证：未授权零请求、ai check 也受授权约束、地址路径拼接、重定向零后续请求、响应回显假密钥不泄露、越界 ID 拒绝、输出文件成组及元数据摘要失配。保留未配置 AI 时旧验证路径不受影响的检查。不要为旧命令补一套只镜像实现的测试，复用现有必要回归。
