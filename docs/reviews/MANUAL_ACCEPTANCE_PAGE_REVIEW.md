# 人工验收指引页面：Codex 方案评审

日期：2026-11-13。仅评审，未实现代码。Codex 同意按下列限定范围实施；这不是新业务规则确认或人工验收签字。

## 三项取舍

1. 第一版账号写在指引中，仅为隔离验收夹具；专项检查对照真实 manual_env.sh 的播种声明。诚实称为“两处声明＋一致性检查”，不称为已经共享单一账号源。本轮不新增 LPB accounts.json、不改已验收脚本，不让通用核心解析 LPB 脚本或硬编码本机路径。样例专项检查显式传入项目路径；缺少源脚本时明确报告未核对，不冒充一致。
2. 暂放 examples/guides/，与当前示范故事位置一致，但加载路径由工作区可选配置提供；核心不写死 examples/ 或 LPB。目录迁移仍另议。Claude 可新增两份 TASK-A-002 / TASK-B-001 指引，不改其他 examples。
3. 这是新增的只读展示功能，为现有验收体验收口，允许实施；不扩展签字/规则录入、执行入口、测试运行器、CI、audit 或目录迁移。

## 必要契约

- 指引增加 story_digest，绑定当前故事内容；ID 存在不代表语义未变。故事改变后，指引标为待核对，不继续当作当前可用操作步骤。仅指引改变不改故事摘要、自动化结果或人工状态。
- 独立严格模型、通用引用校验，CLI 与 Web 复用；不要只在 JS 校验。for 支持真实步骤和分支，未知引用、重复故事指引、重复步骤绑定及格式错误应给出诊断。
- 没配置指引或故事没有指引是正常缺省；已配置但文件损坏/引用错误/版本不匹配要明确展示指引问题，不能静默当作“没有指引”。自动化和规则/人工的原有判定保持独立，不因指引问题改写执行结果。
- 页面顶部放隔离环境、账号表；对应节点附近展开“你做什么／应看到／不一致怎么办”。辅助核对另列，不伪装成界面步骤；命令只作文字，不可点击执行。无签字、执行或通过/不通过按钮。
- 页面区分故事 expected（验收规则）与 guide.see（具体操作现象）。仅文案等价变化可更新指引；若行为违反已确认规则，记录差异，不能修改指引迁就实现。
- 当前故事和指引均在 FlowTree 示例目录，位于 LPB 工作区之外，因此本轮添加指引不应使 LPB 自动化证据过期。未来指引迁入被测项目后，是否排除其工作区指纹另行设计；不得宣称当前机制在任意目录下修改指引都不会失效。
- schema 示例必须与所选方案一致：移除不存在的 accounts.json fixture_ref，改为内嵌的隔离账号资料。用途/显示名不是权限证明，不能把真实 token 或真实用户凭据放入指引。

## 实施与小提交顺序

第一步：实现通用模型/加载及共享校验，写两份故事指引、专项账号比对；覆盖无指引、坏文件、未知/重复引用、故事摘要变化、无本机 LPB 的环境。完成后交 Codex 聚焦核对并作独立小提交。

第二步：把工作区配置接到共享视图与只读页面，补接口和真实浏览器渲染；验证桌面/窄屏/深色、账号与步骤就近、辅助核对区分、测试全名和报告入口保留。更新指引不应改变当前两条故事摘要、证据或人工结果，要有断言。核对通过后作另一个小提交，不 push。

第三步：页面内容逐项核对后，手册去掉重复步骤表，仅保留背景、范围、限制及页面入口；未实现前保留现有可用手册，不提前删除。暂不实现 Markdown 自动生成。

不重跑无关业务测试，不更改 LPB。规则确认/人工验收记录及输入机制仍不在本批范围。
