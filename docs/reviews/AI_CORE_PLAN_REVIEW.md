# AI 核心规划复核（Codex）

日期：2026-11-14。评审对象：`AI_CORE_PLAN.md`。仅评审建议，未实施、未调用 API；不代替负责人批准阶段顺序。

## 总结

A/S/G/E 可以作为职责划分，不必对应四套基础设施。确定性引擎能证明格式、引用、测试执行与证据有效性，不能证明 AI 理解了真实需求。“已有部分只修缺陷”应理解为暂停无关扩展，仍允许起草闭环必要的最小接入改动。不要为“AI 工程”标签牺牲少配置、能使用的产品目标。

## 1. 状态与人确认

- “confirmed 只能由人产生”在当前本地 CLI/文件模型下不能技术证明：AI 也能调用同一命令、写同一文件或冒填姓名。可以承诺生成器无自动确认路径、确认是独立显式动作、绑定对象摘要及声明的确认者；不能把角色字符串当身份认证，也不必为首版增加企业身份系统。测试只证明程序路径边界，不证明真人操作。
- `drafted / validated / confirmed / superseded` 不宜作为一条互斥直线。校验是针对内容的结果，确认是人的声明，取代是版本关联；校验失败、校验错误、内容变化和确认撤回均须能表达，不能掉回一个含糊的 drafted。首版用几类最少事实计算展示，不搭通用工作流引擎。
- 正式内容与确认记录需绑定明确对象及摘要，清楚规定是否还要求校验有效。不得把“移入 stories/”等同于确认，也不要在本批全局禁止已有 draft 故事参与验证：这会改变现有引擎契约。先限定新生成产出不自动进入正式路径；既有规则维度仍如实显示。
- 校验和确认均不代表逻辑验收或人工操作验收通过。确认依据的需求源版本也要记录；需求原文更新后不能只因 YAML 未变就声称仍对应最新需求。

## 2. 评测参照与标注

- US-23/US-24 只有部分核心规则得到明确确认。见 `RULE_CONFIRMATION_US23_US24.md`：重进、重复提交具体行为、审批权限等仍有待决项。不能把完整 YAML 当作逐条已确认标准答案；人工验收通过也不会补齐需求确认。
- 评测前先冻结“原文片段—原子规则—来源位置—确认状态”的小型标注表。区分原文明确要求、推断、夹具、待决，后两类不得混进已确认规则分母。每个标签和修订保留依据。
- “多余”不等于“编造”。合理建议若明确列在待确认项，应与模型把无来源假设写成确定规则分别计数。来源路径/行号存在也不等于内容支持该规则，要人工检查语义对应。
- 先报告格式、明确规则覆盖/遗漏、矛盾、无依据断言和待确认项，给出分子分母及实际案例；不合成单一质量分数。歧义召回需要人工标注分母，不能奖励模型堆满问题。
- F-04 可以作提示文字交互问题的案例，但若原始输入没有必填和可见提示要求，不得以模型没生成这条后来才确认的规则惩罚它。可以单独评估是否发现歧义并提问。

## 3. 诚实边界与复现

- 两条故事已被本团队反复查看，不能再声称其中一条是从未接触的独立留出集；最多叫“本次后续不用于调试的验证样本”。真正的留出样本需另选并在调试前冻结，不必扩大首版范围来凑统计结论。
- 固定输入、提示版本、参数和标注，可复核的是比较报告；外部模型输出不保证逐字可复现。保存输入/输出摘要、模型声明和时间，报告重复运行结果，不把温度设为零当确定性保证。
- 首版手工标注完全可用，评测脚本只做统计和追溯，不要求算法自动判断中文需求语义。不把会写漂亮 YAML 当成能正确生成测试或修复代码。

## 4. 阶段范围与顺序

P1 当前同时包含协议、生成、持久预算、确认/取代和评测报告，过大。建议拆为可独立复验的小批次：

1. 最小接入与调用：已选择的通用协议/DeepSeek、本机配置、发送授权和假服务测试；同时给出一个真正能运行的项目入口，不把全部初始化便利拖到 P4。
2. 单文档起草：严格草稿及来源/内容摘要、独立校验、状态展示；既有引擎仍可独立运行。
3. 确认边界与小型评测：显式确认记录的最小切面，冻结标注表，报告可复核案例与计数。先离线重放保存的输出，真实调用按已批准预算另做。

P0 只索引本次相关现行规范和明确被替代的提案，不以“索引全部历史文档”阻塞开发。P2/P3 保留方向、不提前展开。小批次是实施拆分建议，不意味着已获得实施授权。

## 5. 遗漏的重要工程边界

- 外发范围：显示最终发送内容范围，只读明确指定的需求文件；不自动递归收集仓库、环境变量或源文档引用的链接。长文档先按字节/输入预算拒绝并说明，不静默截断；检索、分块以后再做。
- 提示注入：需求和模型输出均为数据；不得因此执行命令、读取密钥、改目标端点或确认内容。畸形输出、无文本和长度截断均有明确失败路径，不自动重试。
- 预算：请求前先持久登记开始/占用额度，并处理并发和崩溃，不能只累计完成记录；否则超时或两个进程同时调用可绕过上限。无法准确预估金额时只承诺调用数/令牌限制，不声称货币预算硬保证；未知用量保留未知。
- 产出溯源与评测保密：草稿/模型响应可能包含需求原文及敏感内容，不自动把“可入库”解释为“全部适合入库”。保留产物/元数据成组、不覆盖、路径约束及原始响应脱敏的 B1 安全边界。
- 变异评测（P2）：固定适用范围，排除无效/等价变异，区分断言抓住业务错误与测试无法编译、环境失败。不能以写几个易抓的变异声称测试全面。

## 6. 与轮次和发现的衔接

本批确认事件只描述“确认哪份内容”，沿用对象、摘要、操作者声明、时间、依据和更正关联这些概念；不顺便实现人工验收、发现处置、发布批准。执行 run、AI 调用和人工验收轮次分别命名，不复用一个生命周期。未来引用现有记录，而非再复制一套可分别修改的结论。
