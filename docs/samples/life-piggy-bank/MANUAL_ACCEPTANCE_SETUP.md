## 2. 客户端入口

| 项 | 事实（源码） |
|---|---|
| 后端地址 | 编译期变量 `API_BASE_URL`，默认 `http://localhost:8000/api/v1`（`lib/services/api_service.dart`）；用 `--dart-define=API_BASE_URL=...` 指向隔离后端，**不需要改任何源码**。是编译期变量，所以脚本默认固定端口 18765，同一个编译产物可以重复使用 |
| 设备 | 本机 `flutter devices` 有 macOS 桌面和 Chrome。推荐 macOS 桌面：沙盒已带 `network.client` 权限。Chrome 网页端依赖后端 CORS 设置，未验证，不推荐 |
| 会话存储 | 客户端用系统钥匙串保存登录令牌；每次换账号请用界面"退出登录"，结束后也请退出，避免残留令牌指向已删除的临时后端 |
| **钥匙串风险与处理** | 这台机器的登录钥匙串里已经有这个应用的一条会话令牌（我只查了条目属性，没有读取内容；创建于 2026-10-20）。原 `main()` 会启用钥匙串存储，客户端对 401 又会**清除已保存的令牌**，所以直接用 `flutter run` 启动原仓库客户端连隔离后端，会让你原来的会话失效。**本方案不这样做**：用 `manual_client.sh` 在临时副本里加一个只存在于副本的独立入口 `lib/main_manual.dart`，注入内存会话后直接启动真实的 `LifePiggyBankApp`（**不调用原 `main()`**，否则存储会被改回钥匙串）；副本的 bundle id 也改成 `com.lifepiggybank.manualAcceptance`，沙盒容器与偏好设置同原应用分开。退出即丢会话，不读写钥匙串 |
| 账号切换 | 右上角用户名胶囊 → 账户弹层（可滚动，往下拉）→ "退出登录"（无二次确认）→ 回到登录页 |

**MANUAL-01（清理路径越界）的修复**：旧版只检查路径里含 `lpb_manual_client` 字样，`.../lpb_manual_client/../unrelated` 能绕过并删掉旁边的目录。现在：
- 路径必须是绝对、规范的（拒绝 `.`、`..`、重复斜杠、末尾斜杠），目录名必须是 `lpb_manual_client` 或 `lpb_manual_client_<后缀>`；
- 目标本身是符号链接、或路径中任何一级含符号链接（物理路径与给定路径不一致）都拒绝；
- 拒绝与 LPB、HOME 重叠（相等、上级、位于其内部）；
- **所有权标记**：`start` 创建副本时先写 `.flowtree-manual-client`（第一行魔数、第二行 `source=<LPB 物理路径>`，必须是普通文件，不能是符号链接）；`clean` 只删带有效标记的目录，没有标记（包括用户自己的同名目录）一律拒绝；`start` 遇到非空且无标记的目录也拒绝使用；
- **复用前检查**（不只看 `pubspec.yaml`）：来源必须是同一个 LPB；`pubspec.yaml` 与源码一致；`lib/main_manual.dart` 与脚本内置的内存会话入口完全一致；副本 `AppInfo.xcconfig` 里只有一条 `PRODUCT_BUNDLE_IDENTIFIER` 且等于独立 id；`.dart_tool/package_config.json` 存在。任何一项不符就拒绝并提示先 `clean` 再 `start`，**不自动删除**；准备中断（缺少 `.prepared`）则重新准备；
- `rm -rf` 不跟随符号链接，副本内部的符号链接只删链接本身。

**MANUAL-02（clean 必须核对来源项目）的修复**：`clean` 现在除了所有权标记，还要求标记里的 `source=` 等于当前 LPB 的物理路径；魔数有效但来源是另一个项目的副本一律拒绝，退出非 0，目录和沙盒容器都不动。沙盒容器按 bundle id 共用，所以**只有这次确实删掉了本项目的副本，才会清理容器**；`clean` 一个不存在的目录不动容器。

**MANUAL-03（源码变化不得静默复用旧副本）的修复**：副本准备完成时记录**源码摘要**——对 rsync 实际会复制的文件集合（复制与摘要共用同一份排除规则，用 dry-run 列出）逐个取内容摘要再汇总；含**未提交和未跟踪**文件，不依赖 git HEAD。每次 `start` 复用前重新计算并比较，不一致就拒绝并提示"先 `clean` 再 `start`"，**不自动删除**。另外：复制前后各算一次摘要，不一致说明复制期间源码在变，拒绝；副本的 `lib/` 除独立入口外必须与源码一致；旧格式的 `.prepared`（没有摘要）也拒绝。`/tools`（本目录脚本）、`docs`、`backend`、`.flowtree` 等不属于被复制的集合，改动它们不会迫使重建。
- **真实项目上发现并修正的一个误报**：`lib/l10n/generated` 是 Flutter 工具在副本里自己生成/清理的输出，第一次运行后副本里这个目录会变；最初的"副本 lib/ 完整性检查"把它当成副本被改动，导致第二次 `start` 被误拒。已把该目录排除，并补了回归。这个问题假项目测试发现不了，是用真实 LPB 跑第二次 `start` 才暴露的。

**实现方回归结果（收窄排除前）**：`test_manual_client_scope.sh` 共 83 项通过（含 MANUAL-02/03 的新反例），含 MANUAL-01 的原始反例（`..` 绕过，旁边无关目录保持完好）以及不规范路径、目标是符号链接、父路径含符号链接、无标记同名目录、错误/符号链接标记、不合规目录名、HOME/根/LPB/其上级、相对路径、复用前各项被改动、来源不同、中断准备、副本内符号链接不被跟随等。**变异检查**：把 `clean` 临时改回旧的前缀检查，回归在多项上失败（`..`、不规范路径、符号链接、无标记目录等都不再被拒绝），所以这套反例确实能抓住原缺陷。；对 MANUAL-02/03 另做了两个变异：去掉 `clean` 的来源核对，回归有 5 项失败；去掉摘要比较，回归有 1 项失败（`macos/` 新增文件不再被拒绝；其余源码改动仍被副本 `lib/` 一致性检查拦住，两道检查有重叠，所以只有这一项专门依赖摘要）。Codex 独立反例 `test_manual_remaining.py` 3 项全部通过。

**从新位置的实跑**：用 `tools/manual_acceptance/` 下的两个脚本重做了一遍完整流程——后端就绪并播种，客户端 `start`（真实 `flutter run`，用现有缓存构建，打印 VM Service）；SIGINT 结束后客户端退出码 0、进程消失；后端 130 退出；`clean` 删除副本；无残留后端目录或进程；原应用钥匙串条目的修改时间不变；LPB 的 `git status` 只多出 `.flowtree/`（运行产物，被忽略）和新增的 `tools/`。
