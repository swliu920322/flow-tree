## 不同文档怎么连接

产品说明 **为什么/要什么** → 技术设计说明 **如何做到** → 交付卡和任务说明 **本批做什么、何时算完** → 复验说明 **哪些真的验证了、还有什么限制**。

样本材料是这条链的实例，不是另一份通用规范。历史用于解释沿革，不与现行入口争夺“当前结论”。冲突按来源和适用范围核对，不只看“定稿”或文件日期。

## 写文档的最小约定

- 开头说清：给谁读、回答什么问题、状态/适用范围、相关依据；一份文档有一个主要用途。
- 产品/设计是可维护的当前说明；历史交付和验收保留当时事实。更正有来源，不静默把旧失败改成通过。
- 每批只增加必要任务/结果，不复制总规划；完成后链接复验记录。
- 未决项就近写清，设计不冒充运行事实，文档提交不代表提案获批。
- 文件移动后修复 Markdown 链接；历史正文中的旧路径用 [路径映射](archive/PATH_MAP.md)查找。
